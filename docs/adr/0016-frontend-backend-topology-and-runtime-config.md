# ADR-0016：前后端分离以同域反代起步，用运行时配置解耦基址

## 背景

当前 A1 是同源静态 SPA：A2 在 `create_app` 里返回 `index.html` 并挂载
`/static`，前端所有请求都写相对路径 `/api/...`；CSP 为
`connect-src 'self'`，服务端也没有 CORS。桌面壳则由 pywebview 加载
`127.0.0.1` 上的同一份页面。

这带来三个与"前后端分离"直接冲突的耦合：

- 前端无法独立构建、发版与回滚，静态资源和 API 生命周期绑定；
- 换域名或子路径必须改源码，因为基址不是运行时配置；
- 一旦前端独立源站，CSP、CORS、认证传递全部要重新设计。

约束：

- A2 永远只监听 loopback，公网入口只能由边缘/BFF 承担；
- 静态依赖全部本地 vendored，运行时不依赖 CDN 或 Node 服务；
- 继续使用静态 SPA + esbuild/TypeScript，不引入 React/Vue（ADR-0010）；
- 桌面形态必须离线可用，且不能把远程内容加载进带原生桥的 webview；
- 同一份前端产物要能覆盖桌面、同域反代、独立源站与子路径部署。

可选方案：

1. 保持同进程托管，只做代码分层；
2. 同域反代：`/` 由静态站提供，`/api` 转发 A2；
3. 独立源站 + CORS；
4. 增加 BFF，浏览器只访问同源；
5. 改为服务端模板渲染（SSR）。

## 决策

**采用"一份产物 + 运行时配置"，并按"同域反代 → 独立源站 → BFF"分阶段推进。**

1. **运行时配置是唯一基址来源。**
   前端启动时先加载 `/config.json` 或由桌面壳注入的
   `window.__APP_CONFIG__`，校验 schema 后才发第一个业务请求。
   默认值是同源相对基址，因此桌面与同域反代零配置；独立源站只改配置。
   配置只描述传输与端点（`apiBaseUrl`、`authMode`、SSE 参数等），
   业务能力仍以服务端 `/api/capabilities` 为准。

2. **部署形态分四档，逐步迁移。**

   | 形态 | 前端托管 | API | 浏览器跨域 | 认证默认 | 桥 |
   |---|---|---|---|---|---|
   | D 桌面本地 | 本地静态 + loopback | 同源 | 否 | 桌面一次性 token | 有 |
   | B 同域反代 | 静态站/边缘 | `/api` 反代 | 否 | Bearer | 无 |
   | A 独立源站 | 静态站/CDN | 独立 API 源 | 是 | Bearer | 无 |
   | C BFF 公网 | BFF 同源 | BFF 持有 | 否（浏览器只到 BFF） | httpOnly Cookie | 无 |

   先做 B，保留 API 托管的旧入口作为回退；需要 CDN/独立扩容时转 A；
   公网多用户再上 C。

3. **API 版本与握手是分离的前提。**
   目标路径为 `/api/v1/*`，实施时保留 `/api/*` 兼容窗口，由边缘重写或
   后端双挂载。前端在登录前读取 `/healthz` 的 `api_version` 与
   `min_frontend_version`，不兼容时显示阻断页；请求携带
   `X-Frontend-Version`，服务端可返回 `version.frontend_too_old`。
   SSE 重放参数、错误码与能力字段都随 API 版本演进。

4. **静态与 API 的缓存策略分开。**
   带 hash 的前端产物长缓存；`index.html` 与运行时配置 `no-cache`；
   API 与 SSE `no-store`/`no-cache`。当前全局 `no-store` 不能继续覆盖静态资源。

5. **前端禁止新的裸基址字面量。**
   fetch、SSE、XHR 上传统一走同一个 URL 拼接函数；实现阶段用扫描守卫
   防止重新出现 `/api/...` 直写。

6. **A2 的 loopback 边界不变。**
   分离只改变浏览器到边缘的路径，不改变 A2/A3/A4 的绑定位置；
   TLS、CORS、限流、请求 ID 由边缘/BFF 承担。

## 后果

### 好的

- 前端可独立构建、发版、回滚，后端可独立扩容；
- 同一份产物通过配置覆盖四种拓扑，减少分叉；
- 版本握手把"前端落后于 API"从静默故障变成可解释的阻断；
- 缓存策略把静态资源从 `no-store` 中解耦，启动更快；
- 保留 ADR-0010 的静态 SPA 与 vendored 约束，不引入运行时框架。

### 坏的 / 代价

- 需要新增运行时配置的加载、校验与失败页；
- URL 拼接、SSE、上传三条路径都要改造并加守卫测试；
- 同一份产物要在四种拓扑下做 smoke test，测试矩阵变大；
- 边缘/BFF 的部署、TLS、缓存与日志成为新的运维对象；
- `/api` → `/api/v1` 需要一个兼容窗口和弃用策略。

### 中性 / 需要留意

- 配置只描述传输，不承载业务开关，避免出现两套能力事实源；
- 子路径部署要求静态站正确处理 SPA fallback，且不能吞掉 `/api`；
- 桌面形态仍以同源相对基址运行，不需要 CORS；
- 配置错误必须失败关闭，不能退化到"同源默认值猜一下"。

## 复核

- **Verified by**：设计契约见
  [RFC-0003](../rfc/0003-frontend-backend-separation.md)；实现后由
  `REQ-202`–`REQ-204` 的验收项与多拓扑 smoke test 证明。
- **Revisit when**：需要独立前端团队/多前端、CDN 成为硬需求、
  公网多租户上线，或运行时配置出现无法兼容的破坏性变更。
